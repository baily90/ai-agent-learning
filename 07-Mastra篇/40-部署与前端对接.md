# 第40章：部署与前端对接 — 把工单客服从 demo 变成服务

## 引言

第 24 章你学过部署架构（Serverless、Edge、AI Gateway），第 18 章你做过生成式 UI 和流式渲染。现在的问题是：**一个用 Mastra 写好的工单客服，怎么变成「前端能调、生产能跑」的服务？**

这一章打通最后一公里。学完这章，31~40 章的全部知识点就能串成一个完整的「智能工单客服 Agent」。

---

## 40.1 心智转变：从「跑脚本」到「起服务」

Mastra 项目本质是一个**应用**，不是脚本。部署就是把「注册好的 agent/workflow/tool」通过 HTTP 暴露出去。

- Mastra 项目 ≈ 一个 Next.js 应用
- 部署 ≈ next build 然后扔到服务器
- 前端对接 ≈ 前端用 useChat 调后端 API

前面章节在 Studio 里测 agent，那是「开发模式」。生产要把它变成「HTTP 服务」。

---

## 40.2 部署方式一：mastra build（独立服务）

Mastra 自带基于 **Hono** 的服务器，构建后可直接部署：

```bash
npx mastra build    # 构建出可部署的产物
```

构建产物扔到任意 Node.js 环境（VM / 容器 / PaaS）。运行时要求 **Node v22.13+**，也支持 Bun、Deno、Cloudflare。

适合：要完全掌控基础设施、长连接、WebSocket 的场景。

---

## 40.3 部署方式二：Server Adapter（嵌入现有框架）

已有 Express / Next.js / Hono 应用，不想另起服务，用 **server adapter** 把 Mastra 端点挂进去：

```bash
npm install @mastra/express   # 或 @mastra/next / @mastra/hono / @mastra/fastify 等
```

```typescript
import express from 'express';
import { mastraExpress } from '@mastra/express';
import { mastra } from './mastra';

const app = express();
app.use(mastraExpress(mastra));   // 把 Mastra 端点挂到 Express
app.listen(3000);
```

官方 adapter 覆盖：Express、Next.js、Hono、Fastify、Koa、NestJS、Elysia、TanStack Start。

> 这和第 24 章「嵌入现有架构 / Gateway」思路一致——**Mastra 不强迫你换架构，可嵌入现有服务**。

---

## 40.4 部署方式三：云平台 + Mastra Platform

- **Vercel / Netlify / Cloudflare**：Mastra 有内置 deployer，构建后直接部署，享受自动扩缩容。
- **Mastra Platform**：官方托管，提供 Observability（搜索 trace/日志/指标）、Studio（在线调试）、Server（生产 API 服务器）。

选型口诀：**要控制 → 自建（build/adapter）；要省心 → 云平台 / Mastra Platform**。

---

## 40.5 前端对接：复用你的 AI SDK 经验

**Mastra 底层就是 AI SDK**，所以前端对接用的就是你早就会的 useChat：

```typescript
import { useChat } from '@ai-sdk/react';

export function Chat() {
  const { messages, input, handleInputChange, handleSubmit } = useChat({
    api: '/api/chat',          // 指向你的 Mastra 服务端点
  });

  return (
    <div>
      {messages.map(m => <div key={m.id}>{m.content}</div>)}
      <form onSubmit={handleSubmit}>
        <input value={input} onChange={handleInputChange} />
      </form>
    </div>
  );
}
```

你第 4 章学的流式输出、第 18 章学的生成式 UI，在这里**原样生效**——流式协议就是 AI SDK 的。

### 生成式 UI（呼应第 18 章）

工单场景里，agent 调工具（查订单、退款审批）时，前端可渲染对应组件（订单卡片、审批按钮）——正是第 18 章「工具调用驱动 UI」的延续。Mastra 输出的工具调用事件能直接喂给前端 Generative UI 框架。

## 40.6 Harness 与 Sandbox（进阶）

- **Harness**：为「比一次请求活得更久」的 agent 设计——goals（目标）、schedules（调度）、signals（信号）、durable execution（持久执行）。适合「持续监控工单队列、有新单就处理」这类后台长跑 agent。
- **Sandbox**：隔离沙箱里跑代码/文件系统/shell（呼应第 32 章 code mode 的沙箱）。

> 进阶主题，入门了解「它存在、解决什么问题」即可。

## 概念辨析：三种部署方式怎么选

| 方式 | 适合 | 第 24 章对应 |
|---|---|---|
| mastra build | 独立部署、要完全控制 | 自建服务 / 容器化 |
| Server Adapter | 已有 Express/Next 应用 | 嵌入现有架构 / Gateway |
| 云平台 / Platform | 要省心、自动扩缩 | Serverless / Edge |

## 灵魂拷问

**Q1：为什么前端能直接用 useChat 调 Mastra？中间不需要适配层吗？**

因为 Mastra 底层用 AI SDK，输出的流式格式、工具调用事件都是 AI SDK 标准协议。前端 useChat 和后端 Mastra 是**同一套协议的上下游**。这再次印证第 31 章：Mastra 站在 AI SDK 肩膀上，你之前的 AI SDK 知识全部复用。

**Q2：server adapter 和独立 mastra build 的本质区别？**

「谁是主」：独立 build 是「Mastra 自带 Hono 服务」；adapter 是「把 Mastra 塞进你现有服务」。两者跑的 agent/workflow 逻辑完全一样，只是 HTTP 层挂载方式不同。

**Q3：工单客服要上线，除了部署还要考虑什么？**

回顾第 20~24 章：鉴权（谁能调）、安全（prompt 注入防护）、限流（成本控制）、可观测（trace）、评测（质量护栏）。**Mastra 帮你解决开发和编排，但生产治理（鉴权、多租户、合规）仍要靠你的架构能力补上**。

---

## 最佳实践

**✅ DO：**

- 前端复用 useChat，别重造流式轮子。
- 已有服务用 adapter 嵌入，新项目用 build 独立部署。
- 环境变量管理所有密钥，构建产物别带 key。

**❌ DON'T：**

- 别把 Studio 当生产——mastra dev 是开发环境，生产要 build/deploy。
- 别在 adapter 里绕过鉴权——Mastra 端点暴露出去就是 API，要加中间件保护。
- 别一上来就用 Harness 做长跑——先用普通 agent + workflow 跑通。

## 代码实战：工单客服上线三件套

```typescript
// 1. 定义资源（前面章节已建好）
export const mastra = new Mastra({
  storage,
  agents: { support: supportAgent },
  workflows: { ticket: ticketWorkflow },
});

// 2. Express adapter 暴露成 HTTP 服务
import express from 'express';
import { mastraExpress } from '@mastra/express';
import { mastra } from './mastra';

const app = express();
app.use(mastraExpress(mastra));
app.listen(3000, () => console.log('工单客服服务已启动 :3000'));
```

```typescript
// 3. 前端对接
import { useChat } from '@ai-sdk/react';
const { messages, handleSubmit, input, handleInputChange } = useChat({
  api: 'http://localhost:3000/api/chat',
});
```

三步：**定义资源 → 挂 HTTP 服务 → 前端 useChat**。一个完整的工单客服就上线了。
