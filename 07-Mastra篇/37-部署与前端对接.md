# 第37章：部署与前端对接 — 把工单客服从 demo 变成服务

## 引言

第 24 章你学过部署架构（Serverless、Edge、AI Gateway），第 18 章你做过生成式 UI 和流式渲染。现在的问题是：**一个用 Mastra 写好的工单客服，怎么变成「前端能调、生产能跑」的服务？**

这一章我们打通最后一公里：部署选项 + 前端对接。学完这章，31~37 章的全部知识点就能串成一个完整的「智能工单客服 Agent」。

---

## 37.1 心智转变：从「跑脚本」到「起服务」

### 一句话直觉

Mastra 项目本质是一个**应用**，不是脚本。部署就是把「注册好的 agent/workflow/tool」通过 HTTP 暴露出去。

### 前端类比

- Mastra 项目 ≈ 一个 Next.js 应用
- 部署 ≈ `next build` 然后扔到服务器
- 前端对接 ≈ 前端用 `useChat` 调后端 API

你前面章节在 Playground 里测 agent，那只是「开发模式」。生产要把它变成「HTTP 服务」。

---

## 37.2 部署方式一：mastra build（独立服务）

Mastra 自带一个基于 **Hono** 的服务器，`mastra build` 构建后可直接部署：

```bash
npx mastra build    # 构建出可部署的产物
```

构建产物可以扔到任意 Node.js 环境（VM / 容器 / PaaS）。运行时要求 **Node v22.13+**，也支持 Bun、Deno、Cloudflare。

这种方式适合：需要完全掌控基础设施、长连接、WebSocket 的场景。

---

## 37.3 部署方式二：Server Adapter（嵌入现有框架）

如果你已经有 Express / Next.js / Hono 应用，不想另起一个服务，用 **server adapter** 把 Mastra 的端点挂进去：

```bash
npm install @mastra/express   # 或 @mastra/next / @mastra/hono / @mastra/fastify 等
```

```typescript
import { Mastra } from '@mastra/core';
import { mastraExpress } from '@mastra/express';
import express from 'express';

const app = express();
app.use(mastraExpress(mastra));   // 把 Mastra 端点挂到 Express
app.listen(3000);
```

官方 adapter 覆盖主流框架：Express、Next.js、Hono、Fastify、Koa、NestJS、Elysia、TanStack Start。

> 这和第 24 章「AI Gateway / 嵌入现有架构」的思路一致——**Mastra 不强迫你换架构，可以嵌入你现有的服务**。

---

## 37.4 部署方式三：云平台 + Mastra Platform

- **Vercel / Netlify / Cloudflare**：Mastra 有内置 deployer，构建后直接部署到这些平台，享受自动扩缩容。
- **Mastra Platform**：官方托管，提供 Observability（搜索 trace/日志/指标）、Studio（在线调试）、Server（生产 API 服务器）。

选型口诀：**要控制 → 自建（build/adapter）；要省心 → 云平台 / Mastra Platform**。

---

## 37.5 前端对接：复用你的 AI SDK 经验

### 关键认知

**Mastra 底层就是 AI SDK**，所以前端对接用的就是你早就会的 `useChat` / `useCompletion`：

```typescript
// 前端 React 组件
import { useChat } from '@ai-sdk/react';

export function Chat() {
  const { messages, input, handleInputChange, handleSubmit } = useChat({
    api: '/api/chat',          // 指向你的 Mastra 服务端点
  });

  return (
    <div>
      {messages.map(m => <div key={m.id}>{m.content}</div>)}
      <form onSubmit={handleSubmit}>
        <input value={input} onChange={handleInputChange} />
      </form>
    </div>
  );
}
```

你第 4 章学的流式输出、第 18 章学的生成式 UI，在这里**原样生效**——因为流式协议就是 AI SDK 的。

### 生成式 UI（呼应第 18 章）

工单客服场景里，agent 调工具（查订单、退款审批）时，前端可以渲染对应的组件（订单卡片、审批按钮）——这正是第 18 章「工具调用驱动 UI」的延续，Mastra 输出的工具调用事件能直接喂给前端的 Generative UI 框架。

## 37.6 补充：Harness（长跑型 agent）

有些 agent 任务会「比一次请求活得更久」——比如「持续监控工单队列，有新单就处理」。Mastra 的 **Harness** 就是为这种「持久执行」设计的：goals（目标）、schedules（调度）、signals（信号）。

一句话定位：**普通 agent 是一次请求一答；Harness 是持续运行、按目标自主推进的后台 agent**。企业级工单系统里，「自动巡检 + 自动处理」这类需求会用到它。

（Harness 属于进阶主题，入门阶段了解「它存在、解决什么问题」即可，需要时再深入官方文档。）

## 概念辨析：三种部署方式怎么选

| 方式 | 适合 | 你第 24 章的对应 |
|---|---|---|
| `mastra build` | 独立部署、要完全控制 | 自建服务 / 容器化 |
| Server Adapter | 已有 Express/Next 应用 | 嵌入现有架构 / Gateway |
| 云平台 / Platform | 要省心、自动扩缩 | Serverless / Edge |

## 灵魂拷问

**Q1：为什么前端能直接用 `useChat` 调 Mastra？中间不需要适配层吗？**

因为 Mastra 底层用 AI SDK，输出的流式格式、工具调用事件都是 AI SDK 的标准协议。前端 `useChat` 和后端 Mastra 之间是**同一套协议的上下游**。这再次印证第 31 章的判断：**Mastra 站在 AI SDK 肩膀上，你之前的 AI SDK 知识全部复用**。

**Q2：server adapter 和独立 `mastra build` 的本质区别？**

区别在「谁是主」：独立 build 是「Mastra 自带一个 Hono 服务」；adapter 是「把你的 Mastra 实例塞进你现有的服务」。前者适合新项目独立部署，后者适合已有系统要加 AI 能力。**两者跑的 agent/workflow 逻辑完全一样**，只是 HTTP 层的挂载方式不同。

**Q3：工单客服要上线，除了部署还需要考虑什么？**

回顾第 20~24 章：鉴权（谁能调）、安全（prompt 注入防护）、限流（成本控制）、可观测（trace）、评测（质量护栏）。**Mastra 帮你解决了「开发和编排」，但「生产治理」这一层（鉴权、多租户、合规）依然要靠你的架构能力补上**——这正是第 31 章提醒过的。

---

## 最佳实践

**✅ DO：**

- 前端复用 `useChat`，别重新造流式处理的轮子。
- 已有服务用 server adapter 嵌入，新项目用 `mastra build` 独立部署。
- 环境变量管理所有密钥，构建产物别带 key。

**❌ DON'T：**

- 别把 Playground 当生产——`mastra dev` 是开发环境，生产要 build/deploy。
- 别在 adapter 里绕过鉴权——Mastra 端点暴露出去就是 API，要加中间件保护。
- 别一上来就用 Harness 做长跑 agent——先用普通 agent + workflow 跑通，再考虑长任务。

## 代码实战：工单客服上线三件套

```typescript
// 1. 定义资源（前面章节已建好）
// src/mastra/index.ts
export const mastra = new Mastra({
  storage,
  agents: { support: supportAgent },
  workflows: { ticket: ticketWorkflow },
});

// 2. 用 Express adapter 暴露成 HTTP 服务
// src/server.ts
import express from 'express';
import { mastraExpress } from '@mastra/express';
import { mastra } from './mastra';

const app = express();
app.use(mastraExpress(mastra));
app.listen(3000, () => console.log('工单客服服务已启动 :3000'));
```

```typescript
// 3. 前端对接
import { useChat } from '@ai-sdk/react';

const { messages, handleSubmit, input, handleInputChange } = useChat({
  api: 'http://localhost:3000/api/chat',
});
```

三步：**定义资源 → 挂 HTTP 服务 → 前端 useChat**。一个完整的工单客服就上线了。
