# Lab 04 · 结构化输出

> 配套第 05 章。目标：让 AI 返回「类型安全」的 JSON，而不是自由文本。

## 跑起来

```bash
cp .env.example .env      # 填 DeepSeek key
npm install
npm run ask "我的订单 20231001001 三天了还没发货，气死我了，我要退款！"
```

你会看到 AI 返回一个**严格符合 zod 定义的 JSON**（订单号、问题类型、情绪、摘要）。

## 学什么

- `Output.object({ schema })`：强制 AI 输出符合 zod schema 的结构
- zod schema 就是"给 AI 的接口契约"，返回的 `result.object` 有完整类型提示
- 为什么重要：AI 返回自由文本没法可靠地写进数据库、传给下一步逻辑

## 练什么（挑战）

**挑战 1：字段必填**

给 schema 加一个 `urgency: z.number().min(1).max(5)`（紧急度 1-5），重新跑，看 AI 是否自觉打分。

**挑战 2：解析失败处理**

故意给一段跟客服完全无关的话（比如"今天天气真好"），看 `issueType` 会被填成什么。思考：真实项目里怎么处理这种"AI 抽不出字段"的情况。

**挑战 3：对应到客服项目**

想想客服系统里哪些地方需要结构化输出——比如"用户意图分类""工单字段自动填写"，这就是你之后要做的。
