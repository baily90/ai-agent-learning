# Lab 08 · RAG 基础

> 配套第 09 章。目标：跑通 RAG 完整流程，理解"检索增强生成"到底在干什么。

## 跑起来

```bash
cp .env.example .env      # 填 DeepSeek key + 硅基流动 SiliconFlow key（两个都要）
npm install
npm run ask "我买的东西已经发货了，还能退款吗？"
npm run ask "优惠券过期了还能用吗？"
npm run ask "今天天气怎么样？"    # 观察：知识库里没有，AI 应该诚实说不知道
```

## 学什么

- **RAG = 检索 + 生成**：先从知识库检索相关文档，再把文档喂给 LLM，让它"有据可查"地回答
- **embedding**：把文本转成向量（BGE BAAI/bge-large-zh-v1.5）
- **余弦相似度**：衡量问题和文档的"语义接近程度"
- 为什么需要 RAG：LLM 不知道你的私有数据（退款规则、售后政策），RAG 把这些"外挂"给它

## 练什么（挑战）

**挑战 1：看"没有 RAG"会怎样**

把 `system` 里的 `知识库：${context}` 删掉，重新跑，观察 AI 是否开始"瞎编"退款规则。

**挑战 2：扩充知识库**

往 `faqDocs` 里加更多条目（发货时效、发票、改地址…），验证检索是否还能准确命中。

**挑战 3：对应客服项目**

这就是客服系统 FAQ 能力的最小实现。想想：真实项目里知识库应该存哪（数据库？文档？），怎么动态更新。
