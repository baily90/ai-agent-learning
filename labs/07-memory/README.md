# Lab 07 · 对话记忆与上下文管理

> 配套第 08 章。目标：让 AI "记住"多轮对话，理解短期记忆与滑动窗口。

## 跑起来

```bash
cp .env.example .env      # 填 DeepSeek key
npm install
npm run ask
```

进入交互式对话，试试：

```
你：我叫小明
AI：你好小明！（记住了）
你：我叫什么？
AI：你叫小明 ✅（能记住，因为有消息历史）
你：exit
```

## 学什么

- **LLM 本质是无状态的**：每次调用不记得上次说了啥
- **消息历史（messages）**：把之前的对话原样传回去，就是最基础的"记忆"
- **滑动窗口**：只保留最近 N 条，防止上下文越滚越长、token 爆炸

## 练什么（挑战）

**挑战 1：看 token 增长**

把 `MAX_HISTORY` 改成很大的数（比如 100），多聊几轮，观察每次调用的 token 如何快速增长（这就是为什么必须做窗口限制）。

**挑战 2：摘要压缩**

滑动窗口的缺点是"丢掉早期信息"。试试实现"摘要压缩"：当历史超过阈值时，先调一次 LLM 把历史摘要成一段话，再继续——这就是长期记忆的雏形。

**挑战 3：对应客服**

想想客服场景：用户来回问了好几个问题，客服 AI 需要记住"他刚才说的是哪个订单"。这就是 memory 在客服里的作用。
