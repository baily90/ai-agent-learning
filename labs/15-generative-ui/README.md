# Lab 15 · 生成式 UI（Generative UI）

> 配套第 17+18 章。目标：工具调用不再只是返回文本，而是驱动前端渲染成「组件」。

## 跑起来

```bash
cp .env.local.example .env.local   # 填 DeepSeek key
npm install
npm run dev                        # 打开 http://localhost:3000
```

然后在聊天框输入：`我的订单 20231001001 到哪了？`

你会看到——AI 调用 `getOrder` 工具后，**不是返回一段文字，而是渲染出一张"订单卡片"**（订单号、状态、商品、物流、金额）。

## 学什么

- **生成式 UI 的核心**：工具返回结构化数据 → 前端把它渲染成组件（而不是纯文本）
- 工具 part 类型是 `tool-<工具名>`，`part.output` 就是工具返回的数据
- 前端 `useChat` + 后端 `streamText` 的完整链路

## 结构

```
app/
├── page.tsx          # 前端聊天界面 + 渲染组件
├── layout.tsx        # 根布局
└── api/chat/route.ts # 后端 API（streamText + 工具）
ai/tools.ts           # 工具定义（查订单，返回结构化数据）
components/order-card.tsx  # 订单卡片组件
```

## 练什么（挑战）

**挑战 1：加更多组件**

再写一个"物流轨迹"工具，返回物流节点数组，前端渲染成时间线组件——感受"AI 决定调哪个工具，前端渲染对应组件"的威力。

**挑战 2：对应客服项目**

这就是客服系统 h5 端的目标形态：用户问订单 → 出订单卡片；问商品 → 出商品卡片；而不是干巴巴的文字。

**挑战 3：流式 + 生成式 UI 结合**

观察：文本是流式打字的，而工具组件是"查完一次性渲染"的。想想真实产品里怎么让两者衔接更自然。
