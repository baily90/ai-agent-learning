# Lab 17 · 评估（LLM-as-judge）

> 配套第 21 章。目标：用"另一个 LLM"当裁判，自动评估回答质量。

## 跑起来

```bash
cp .env.example .env      # 填 DeepSeek key
npm install
npm run ask
```

会自动跑 3 个评估用例，每个都生成回答 + 打分 + 理由，最后输出平均分。

## 学什么

- **评估数据集**：一组（输入 + 评估标准），像单元测试的用例
- **LLM-as-judge**：用另一个 LLM 当裁判打分（省去人工评测）
- 为什么重要：改了 prompt / 工具后，怎么知道"变好了还是变坏了"？靠评估

## 练什么（挑战）

**挑战 1：A/B 对比**

改 `SYSTEM`（比如换个更详细的客服 prompt），重新跑，对比平均分——这就是"改 prompt 后到底有没有变好"的量化答案。

**挑战 2：扩充评估集**

把 `evalSet` 扩到 10 条，覆盖更多客服场景。想想：怎么保证评估集"有代表性"。

**挑战 3：对应客服项目**

这是客服系统上线前的关键一环——用评估集回归测试，防止改坏已有能力。上一轮你在 18-observability 里做过的"改 description 实验"，就可以用这个评估自动量化。
